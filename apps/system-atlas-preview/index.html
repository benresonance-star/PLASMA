Cross-cutting Plasma languages

Small reusable languages shared by every domain. Domain languages compose these rather than inventing their own state, evidence or history semantics.

shared semantics · stable contracts

Band 3

Authoritative operation lifecycle

This is how a language becomes action. Executors may propose results; only validation and the transaction boundary can change canonical world state.

proposal ≠ truth
01

Semantic operation

Target refs · intent · parameters · preconditions · requested evidence.

02

World slice

Read the smallest authoritative state and dependencies required for the task.

03

Execute

Resolver · deterministic algorithm · solver · bounded agent · external tool.

04

Candidate result

Patch · claims · representations · measurements · evidence. Not yet truth.

05

Validate

Check invariants, contracts, topology, units, constraints and acceptance evidence.

06

Transaction gate

Accept atomically or reject without corrupting the world.

07

Authoritative world

Commit revision, provenance and stable identity; then invalidate actual dependents.

Authoritative World→Dependency graph marks only affected derivations stale → relevant domain capabilities can run next → new proposals return through the same lifecycle.
Interaction rule: domain languages do not call one another or mutate the world directly. They communicate through shared world state, typed operations, dependencies, claims and evidence.
