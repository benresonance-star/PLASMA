# Milestones and acceptance gates
The user's instruction authorizes the consolidation candidate. Subsequent software milestones below are the next implementation programme, not completion claims.

## M0 — consolidated baseline (this change)
Deliver one entry point, preserved Foundry/terrain source, six draft contracts, decision register, evidence matrix, reference artifacts and generated reading copy.
Verify source JSON round-trip preservation, relative references and schema reference consistency. Record checks separately from runtime tests.
Exit: reviewable pinned commit and draft PR; no release/production claim. Missing full chat transcripts remain explicit in CON-010 through CON-014.

## M1 — one coherent wall editing build
1. Recover the integrated Kernel v0.3 application and all relevant RC-02 sources; import original bytes with digests and a reproducible build. Select one kernel owner and map legacy fields to draft contracts.
2. Run the reference fixture: +500 mm preserves a conflicted preview and accepted R0; +150 mm produces W17 +150 / B03 3650 / C04 1000 at R1; undo produces R2 without deleting R1.
3. Reject stale base, duplicate-key/different-payload, superseded worker, missing hard evidence and ambiguous hard references.
4. Use a normal browser origin, close the browser process, reopen and recover the same head/application state. Inject failures before/after checkpoint writes, corrupt primary storage and test backup recovery. A success message must not precede durable acceptance.
5. Route one wall operation through the actual pinned OCCT provider: isolated B-rep candidate, tolerance/healing validation, correspondence and atomic semantic/representation publication.
6. Measure desktop and physical iPhone interaction, including currentness feedback. Set target workloads, latency/memory budgets and percentile sample protocol before running; report achieved results honestly.

Exit: one exact commit/build, reproducible fixture, durable state evidence, stale-result rejection, one exact geometry operation and physical-device observations. Unsupported production features stay labelled unsupported.
Implementation sequencing may use a local transactional adapter first; a shared database and two-client test are separate gates before multi-user claims.

## M2 — terrain T1 then T1R on the same contracts
Registered points + boundary + one breakline, precise plan/3D/section editing, reversible CRUD and shared human/AI command path.
Prove evaluator-specific conservative influence, stable anchors, source replacement, coupled solve groups, local/full equivalence and explicit currentness.
Exercise near-coincident/crossing constraints, rapid drags, long histories, 100,000-control surrounding context, concurrent proposals, undo/rebase and nonlocal effects of boundary-preserving edits.
Benchmark invalidation/transfer cost before a worker pool or GPU expansion. Do not broaden materially into T2/T3 until the inherited T1R gate passes.
Exit: same unchanged kernel contracts govern wall and terrain; identify necessary contract revisions before freezing schemas.

## M3 — architectural delivery slice
Choose one real site and bounded housing option. Introduce evidence-backed context, one defensible quantity/cost chain and one fabrication/installation interface.
Separate design choice, cost assumption and compliance interpretation. State unavailable specialist checks explicitly.
Measure designer effort, rework, time to a reviewable option and uncertainty reduced. This determines whether further platform complexity delivers value.

## R1 — research tracks
Botanical pattern test, larger fields/ecosystems, specialist fabrication exchange, robotic erection and advanced agent orchestration remain individually scoped.
They may produce experiments and decisions without becoming prerequisites of M1/M2.

## Stop conditions
Do not advance a dependent gate when evidence is stale, incomplete, fixture-only beyond its stated scope, or based on an unqualified fallback.
Any expansion of kernel primitives needs a concrete failing cross-domain case and an explicit design decision.
Prefer extracting a proven mechanism from the existing repository over wholesale adoption; use the preserved 15-target audit.
